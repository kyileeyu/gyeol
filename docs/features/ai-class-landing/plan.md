## 문제

숨고·스레드로 꾸준히 문의가 들어오지만 정식 랜딩이 없어 문의 채널이 분산되고 첫 인상을 통제할 수 없다. 특히 입문 과외부터 기업 AX(AI 전환 컨설팅)까지 다양한 스펙트럼을 소화하는 역량이 외부에 전혀 드러나지 않아 포지셔닝이 좁게 인식된다. 방문자가 "이 사람이 무엇을 얼마나 할 수 있는가"를 확인하고, 자신의 상황에 맞는 다음 단계로 나아가는 단일 동선이 없다.

## 사용자

**1순위 — 비개발 직장인·1인 사업자 (입문·자동화)**
실제 학생 3케이스(자동화 사업가, 디자이너, 금융 IM 직장인)로 검증. 공통 특성:
- 환경 세팅·용어에서 막혀 혼자 못 나가는 상태.
- "어디에, 어떻게 쓰지?"를 기능보다 먼저 묻는 패턴(활용처 불명확).
- 비용·토큰·과금에 민감.

**2순위 — AI 도구 사용 중이지만 더 깊은 자동화·에이전트를 원하는 중급자**
n8n·Claude·API 등을 써봤지만 에이전트 구조 설계나 서비스 MVP 출시까지는 막혀있는 상황.

**3순위 — 기업·팀의 AI 전환을 고민하는 의사결정자**
개인 과외 맥락이 아닌 조직 단위 AX 컨설팅 수요. 이 페이지가 첫 진입점이 되되 상담으로 바로 연결.

## MVP 범위

원페이지 랜딩. **7개 섹션**. 기존 `code` 프로젝트 안 `/ai` 라우트로 구현.

### 섹션 구성

**S1 — Hero**

- 헤드라인 (안): "목표에 맞게, 매번 새로 설계합니다." 또는 "원하는 걸 함께 만들어봅니다."
  - 방향: 맞춤·가능성 강조. 입문자 한정 뉘앙스를 피한다. (최종 카피는 열린 질문 참조)
- 서브: "AI 컨설팅·과외 — 용어 입문부터 기업 AI 전환까지. 직무와 목표에 맞춰 매번 새로 설계합니다."
- CTA 버튼 1개: "상담 신청하기" → 페이지 내 Contact 섹션으로 smooth scroll.
- 배경: 설백(`#FAFBFC`). Hero 물결 셰이더 미사용 (본사 시그니처 희석 방지).

**S2 — 누구를 위한가**

체크리스트 형식. v1의 입문자 3항목에서 스펙트럼을 넓힌다.

- "AI 도구를 쓰고 싶은데 환경 세팅·용어에서 막혔어요."
- "업무 자동화는 해봤는데, 더 깊은 에이전트·파이프라인으로 가고 싶어요."
- "아이디어가 있는데 작동하는 서비스로 만드는 방법을 모르겠어요."
- "팀이나 회사 차원에서 AI 도입 방향을 잡고 싶어요."
- "이 중 하나라도 해당한다면, 함께 설계해볼 수 있습니다."

**S3 — 페인포인트→해결**

roadmap.md 검증 데이터 기반 3개 카드. v1과 골격 동일, 카피 미세 조정.

1. "환경 세팅이 첫 번째 벽" → "Mac·Windows 맞춤 세팅 가이드로 1회 완파"
2. "용어를 모르면 질문도 못 한다" → "용어집 핸드아웃 + 첫 회차에서 정리"
3. "프롬프트를 어떻게 써야 할지 모른다" → "대화 루프 패턴을 몸에 익힐 때까지 함께"

수치 표기 의도적 배제. 검증 근거는 익명 카피 톤으로만.

**S4 — AI 사다리 (v1 커리큘럼·트랙 섹션 전면 교체)**

핵심 프레이밍: **닫힌 커리큘럼이 아니라 가능성의 스펙트럼**.

- 섹션 헤더: "어디까지 가고 싶으신가요."
- 서브 카피: "roadmap.md의 트랙은 예시일 뿐입니다. 직무와 목표에 따라 매번 새로 설계합니다."
  - (서브 카피는 내부용 톤 — 실제 페이지에는 "무엇을 만들고 싶은지 이야기해주시면, 그것부터 시작합니다" 류로 다듬기)

5단계 사다리 (위로 갈수록 깊어지는 스펙트럼):

| 단계 | 제목 | 한 줄 설명 |
|---|---|---|
| 1 | **입문 과외** | 용어·환경 세팅·프롬프트법. 코드 한 줄 안 써도 됩니다. |
| 2 | **업무 자동화** | 문서·PPT·데이터·리서치. 반복 업무를 AI가 대신합니다. |
| 3 | **AI 에이전트 설계** | 내 일을 대신하는 팀. 스킬과 서브에이전트로 파이프라인 설계. |
| 4 | **나만의 서비스 (MVP)** | 아이디어를 작동하는 웹·앱으로. 코드 없이도 출시까지. |
| 5 | **기업 AI 전환 (AX)** | 팀·조직 단위 AI 도입 방향 설계. 상담으로 시작합니다. |

표현 원칙:
- "이 다섯 단계를 모두 해야 한다"는 뉘앙스 금지. "지금 계신 곳에서 시작합니다"로.
- AX는 가격·패키지 비노출. "상담으로 시작합니다" 텍스트만.
- 각 단계 카드에 "이런 것도 가능합니다" 예시 1~2줄 (roadmap.md 3트랙 내용을 흡수해 재배치).

**S5 — 차별점**

숨고 소개글의 4종 차별점을 카드 또는 목록으로 명시. v1에는 없던 섹션.

- 섹션 헤더: "다른 강의와 무엇이 다른가요."
- 4종 항목:
  1. **1:1 맞춤 설계** — "직무·목표에 맞춰 매번 새로 설계합니다. 저장된 데이터가 한계가 아닙니다."
  2. **실제로 돌아가는 산출물** — "강의용 예제가 아닙니다. 수업 끝에 실제로 쓸 수 있는 결과물이 나옵니다."
  3. **용어부터 차근차근** — "코드를 몰라도 됩니다. 클로드와 대화하는 법부터 함께합니다."
  4. **전용 복습자료 PDF** — "그날 막힌 지점을 정리한 자료를 수업 후 보내드립니다."
- 형식: 1:1 or 그룹 / 온라인(화상) or 오프라인(대면) 선택 가능 — 한 줄 추가.

**S6 — 진행 방식 + 강사 소개**

- 1:1 또는 그룹, 온라인(화상) or 오프라인(서울 카페·코워킹) — 상황에 따라 조율.
- 체험(1시간) → 트랙 결정 → 코스 시작 흐름.
- 가격 숫자 비노출. "상담 시 안내" 톤.
- 강사 소개: FE 개발 출신, 매일 Claude Code·n8n으로 직접 자동화 중. **상세 스토리는 `/me` 링크로 위임.** 한 줄 예시: "매일 직접 돌리면서 가르칩니다. (더 알아보기 →)"

**S7 — Contact / 상담 신청**

- 폼 필드 4개:
  1. 이름 (text, 필수)
  2. 이메일 (email, 필수)
  3. 관심 주제 (select, 필수) — **v2 확장된 5개 옵션**:
     - 업무 자동화 (문서·데이터·반복 업무)
     - AI 에이전트 설계
     - 나만의 서비스 만들기 (MVP)
     - 기업 AI 전환 (AX)
     - 아직 모르겠어요
  4. 만들고 싶은 것 또는 막히는 지점 (textarea, 필수)
- 제출 성공: "곧 연락드리겠습니다" 인라인 메시지. 페이지 전환 없음.
- Honeypot 필드 + Zod 서버 검증 (기존 패턴 그대로).
- 자동 응답 메일: 결 Contact 자동 응답 패턴 재사용, 강의 문맥으로 변형.

## 분업 구조 — `/me` 소개 허브와의 역할 재조정

v2에서 AX가 `/ai`에 포함되면서 `/me`와의 분업 경계를 명확히 한다.

| 역할 | `/ai` 컨설팅·과외 랜딩 | `/me` 소개 허브 |
|---|---|---|
| 목적 | 전환 (상담 신청) | 권위 형성 + 라우팅 |
| AX 노출 | 사다리 최상단 — 가능성 시그널 + 상담 CTA | AX 시그널 카드 — 목적지를 `/ai`로 라우팅 |
| 강사 스토리 | 한 줄 + `/me` 링크 위임 | 스토리·관점·배경 전담 |
| SNS 링크 허브 | 없음 | S4 전담 |
| 후기/실적 | 후속(v1.1) | S5 전담 |

**`/me` 수정 필요 사항 (분업 재조정)**:
- S3 AX 시그널 카드 — 목적지: "가벼운 문의 폼으로 smooth scroll" → **`/ai`로 라우팅**으로 변경 권장.
  - 근거: `/ai`에 이미 AX가 포함되어 있으므로, `/me` 폼으로 받는 것보다 `/ai` 상담 폼으로 직행하는 것이 동선 일관성이 높다. `/me` 폼은 "어디 맞는지 모르겠다"는 라우팅 목적으로만 남긴다.
  - 조정안: AX 카드 CTA "이야기 나눠보기" → `/ai#class-contact` 로 연결.
  - 이 변경은 `/me` plan.md의 소규모 업데이트가 필요하다. (designer·developer에 전달 필요)

**교차 링크 원칙 (확정)**:
- `/ai` S6 강사 소개 → `/me` 링크.
- `/me` S3 AI 강의 카드 → `/ai`.
- `/me` S3 AX 카드 → `/ai#class-contact` (v2 조정안).

## 가정

- 기존 Resend 도메인(`gyeol.page`) SPF/DKIM 인증은 완료 상태다. 강의 문의 자동 응답도 같은 인증을 재사용한다.
- 체험 후기가 현재 공개 동의 건 미만이다. 후기 섹션을 MVP에서 제외한다.
- `ai.gyeol.page` 서브도메인 DNS는 아직 설정되지 않았다. rewrite 설정과 함께 DNS CNAME을 추가해야 한다.
- 강의 문의는 기존 결 본사 문의(`hi@gyeol.page`)와 같은 받은편지함으로 수신해도 운영상 문제없다.
- `/me` 소개 허브는 `/ai`보다 먼저 또는 동시에 구현된다고 가정하지 않는다. `/ai`는 단독 동작 가능해야 한다.
- roadmap.md의 3트랙(영상 자동화 / 업무·데이터 / 디자이너)은 실제 수강생 케이스에서 도출된 예시이며, AI 사다리 섹션 각 단계의 "예시 설명" 안에 자연스럽게 흡수된다.
