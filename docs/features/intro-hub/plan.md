# Shannon — 개인 소개/권위 허브

## 문제

유튜브·인스타·스레드·숨고에서 Shannon을 처음 만난 사람이 "이 사람이 누구이고, 무엇을 할 수 있는가"를 한 곳에서 확인하고 다음 단계(강의 / 제작 / AX 상담)로 이동할 수 있는 입구가 없다. 현재는 채널마다 bio가 파편화되어 있고, 링크인바이오 도구(리틀리 등) 대신 자체 소유 허브가 없어 컨텍스트와 권위가 유실된다.

## 사용자

**1순위 — 콘텐츠 경유 방문자**: 유튜브·인스타·스레드에서 Shannon의 콘텐츠를 보고 프로필 링크를 클릭한 사람. 직접 구매 의사보다 "이 사람이 누구인지" 확인 목적.

**2순위 — 숨고 문의 전 검증자**: 숨고에서 AI 강의를 검색하다가 Shannon의 프로필 링크를 클릭한 사람. 신뢰 검증 목적.

**3순위 — 명함/지인 경유**: `/card` QR 또는 지인 소개로 진입. 웹 제작 문의 가능성이 높음.

공통 행동: 한 페이지에서 3~5분 안에 "이 사람 믿을 만하다 / 다음 단계로 가겠다"를 결정한다.

## 성공 기준

KPI 1순위 — 허브 → `/ai` 클릭스루율

- [ ] 허브 진입 후 `/ai` 강의 페이지 이동(`hub_to_ai_click` 이벤트) 클릭스루율 **10% 이상** (런칭 후 4주 측정).
- [ ] 가벼운 문의 폼 제출 완료(`hub_inquiry_submit`) 전환율 **2% 이상** (이 허브의 문의는 "어디에 맞는지 모르겠다"는 라우팅 목적이므로 강의 랜딩보다 낮게 설정).
- [ ] SNS/외부 링크 클릭(`hub_social_click`, `hub_outbound_click`) 월간 합산 **30회 이상** (리틀리 흡수 효과 측정).
- [ ] 스크롤 깊이 75% 이상 도달 비율 **35% 이상** (권위 섹션까지 읽는 비율).
- [ ] 체류 시간 중앙값 **90초 이상** (기준선 수집 후 3개월 차에 평가).

보조 지표 (측정만, MVP 판단 외)

- `section_view` 섹션별 발화 비율 (어느 섹션이 다음 단계 결정에 기여하는지).
- `/ai` 외 아웃바운드(`hub_outbound_click { target: "work" | "card" }`) 비율.

### 제안 이벤트명 목록

| 이벤트명 | 발화 시점 |
|---|---|
| `hub_view` | 페이지 마운트 1회 |
| `hub_to_ai_click` | `/ai` 강의 CTA 또는 서비스 카드 클릭 |
| `hub_to_work_click` | 결 제작 카드 또는 `gyeol.page` 링크 클릭 |
| `hub_inquiry_submit` | 가벼운 문의 폼 제출 완료 |
| `hub_social_click { platform }` | 유튜브·인스타·스레드·숨고 링크 클릭 |
| `hub_outbound_click { target }` | 허브 내 외부 링크 클릭 (SNS 제외) |
| `section_view { section }` | 각 섹션이 뷰포트 50% 진입 시 |

## MVP 범위

단일 페이지(원페이지). 신규 라우트(`/me` 추천 — 근거는 아래 결정 필요 섹션 참조). 6개 섹션.

### 섹션 구성

**S1 — Hero / 정체성**
- 헤드라인: **"유승현입니다"** (확정 — 실명·미니멀). 영문 핸들 Shannon이 아닌 본명을 전면에 둔다. 권위는 아래 섹션이 쌓는다.
- 서브 한 줄: FE 개발자 출신으로 AI 강의, 인터랙티브 웹 제작, 기업 AI 전환까지 함께 봅니다.
- 얼굴 사진 포함 — 개인 권위 허브이므로 `/card`와 달리 얼굴 노출 확정. (사진은 `/card/profile.webp` 재사용 또는 더 자연스러운 컷으로 교체.)
- 배경: 결 컬러 토큰 설백(`#FAFBFC`). Hero 물결 셰이더 미사용 (본사 시그니처 희석 방지).
- CTA 없음 — Hero는 인식 단계. 스크롤이 CTA.

**S2 — 스토리·관점**
- 제목(안): "왜 이 일을 하는가."
- FE 개발 출신 → AI 도구 실무 적용 → 강의 → 웹 제작 → AX 비전까지 흐름을 3~4 문장으로.
- 자의식 과잉 금지 — 학교·나이·이직 이력 배제. "내가 겪었고, 지금 이 일이 재미있다"는 관점 중심.
- 한 줄 핵심 관점: "기술은 결국 사람이 쓰는 것. 막히지 않게 설계하는 것이 내 일입니다."
- 이 섹션은 `/ai` plan.md S5(강사 소개)의 부담을 흡수한다. `/ai`에서는 이 페이지로 링크하고 상세 스토리는 생략한다.

**S3 — 무엇을 해주나 (서비스 라우팅)**
- 섹션 헤더: "지금 어디쯤 계신가요."
- 3개 카드 — 각 카드가 방문자 상황에 맞는 다음 단계로 연결.

| 카드 | 제목 | 한 줄 | 연결 |
|---|---|---|---|
| AI 강의 | AI, 나도 쓸 수 있을까요 | 비개발자를 위한 1:1 AI 코딩 강의. 막히는 지점부터. | `/ai` 이동 |
| 웹 제작 | 브랜드에 맞는 페이지가 필요하다면 | 결이 맞는 인터랙티브 웹. | `gyeol.page` 이동 |
| AX 비전 시그널 | 팀의 AI 전환까지 함께 본다면 | 기업 AI 전환(AX) 컨설팅 — 방향과 맥락을 함께 설계합니다. | 가벼운 문의 폼으로 smooth scroll |

- AX 카드는 명시적 패키지·가격 없음. "함께 봅니다" 수준의 비전 시그널만. 실제 CTA는 폼.
- AX 카드 CTA 버튼 문구: "이야기 나눠보기".

**S4 — 콘텐츠·SNS 링크 허브 (리틀리 흡수)**
- 섹션 제목: "채널에서 만나요" 또는 "더 보기".
- 링크 4종: 유튜브 / 인스타그램 / 스레드 / 숨고 (AI 강의 프로필 직링크).
- 각 링크에 한 줄 맥락: 어떤 콘텐츠를 올리는지.
- 이 섹션이 SNS bio → 허브 → 각 채널로 아웃바운드하는 "진짜 리틀리" 역할을 한다.
- SNS 계정 URL은 실제 URL로 채워야 함 (열린 질문 참조).

**S5 — 신뢰/실적**
- 공개 동의받은 후기가 있을 경우: 텍스트 후기 카드 1~3개 최소.
- 없을 경우: 섹션 생략. v1.1에 추가.
- 대안 실적 표현 **(확정 채택)**: "업종이 제각각인 비개발 직장인들이 똑같이 막힌 지점을 검증한 커리큘럼" 류의 **익명 표현** 사용. 학생 이름·숫자 노출 없이 신뢰만 전달. (roadmap.md 3/3 교차검증 사실의 익명 카피화.)
- 결 웹 제작 작업물(`dewstone.kr` 등)은 `gyeol.page/work`와 중복이므로 허브에서는 링크만 ("포트폴리오 보기 →").

**S6 — CTA / 가벼운 문의**
- 섹션 헤드: "어디서 시작할지 모르겠다면, 먼저 이야기 나눠보세요."
- 폼 필드 3개 (강의 랜딩보다 더 가볍게):
  1. 이름 (text, 필수)
  2. 이메일 (email, 필수)
  3. 어떤 부분이 궁금한가요 (textarea, 필수) — 자유 서술. 방문자 스스로 맥락 제공.
- 제출 성공: "곧 이야기 나눠보겠습니다" 인라인 메시지. 페이지 전환 없음.
- Honeypot 필드 + Zod 서버 검증 (기존 패턴 그대로).
- 자동 응답은 결 본사 자동 응답 패턴 재사용. 수신은 `hi@gyeol.page` 동일.

**Footer**
- 결 본사 헤더·푸터 공유 — 분업 일관성. `/ai`와 동일 원칙.

### 재사용 vs 신규

**재사용 (코드 변경 없음)**
- 컬러 토큰 7종 (`globals.css` `@theme inline` 블록) — 그대로 상속.
- Pretendard 폰트 (`layout.tsx` `next/font/local`) — 그대로 상속.
- `track()` 함수 (`src/lib/analytics.ts`) — 신규 이벤트만 union 추가.
- Resend + Honeypot + Zod 패턴 — `src/app/api/hub-contact/route.ts` 신규 작성 (기존 라우트 불가촉).
- `/card/profile.webp` 프로필 사진 — 허브에서 재사용 가능. 또는 교체.
- `PROFILE` 상수 (`src/features/card/lib/profile.ts`) — 허브 `profile.ts`에서 import 공유.
- 결 헤더·푸터 — 공유 확정.

**신규 작성**
- `src/app/me/page.tsx` — 라우트 + metadata export (서버). 라우트명 `/me` 추천 기준은 결정 필요 섹션 참조.
- `src/features/intro-hub/` — FSD 패턴. 섹션 컴포넌트 6개 + HubContactForm 클라이언트 컴포넌트.
- `src/app/api/hub-contact/route.ts` — 허브 문의 전용 Route Handler.
- OG 이미지 (`public/og/me.png`, 1200×630) — 얼굴 사진 + 이름 + 한 줄 정의.
- `src/app/sitemap.ts` — `/me` 항목 추가 (priority 0.7, changeFrequency: "monthly").
- `src/lib/analytics.ts` — `hub_*` 이벤트 union 추가.

## 가정

- Shannon의 SNS 채널(유튜브·인스타·스레드·숨고 프로필)은 모두 실제 URL이 확보되어 있다.
- 후기 공개 동의를 받은 건이 MVP 시점에 없을 수 있으므로, S5(신뢰/실적)는 대안 카피로 대체한다.
- Resend 도메인(`gyeol.page`) SPF/DKIM 인증은 이미 완료 상태다.
- `/card/profile.webp`는 개인 권위 허브에 재사용해도 브랜드 톤이 충분히 맞는다고 가정한다. (더 자연스러운 사진이 있으면 교체 — 디자인 단계 결정.)
- 가벼운 문의는 강의 / 제작 / AX 구분 없이 통합 수신해도 운영상 문제 없다. 필드에서 맥락을 읽고 라우팅한다.
- 허브 진입 후 AX 문의가 발생해도 MVP에서는 별도 대응 프로세스 없이 `hi@gyeol.page`로 처리한다.

## 결정 완료 (사용자 확인 — Q1~Q4 모두 추천대로 채택)

아래 4건은 추천안 그대로 확정됐다. 근거는 참고용으로 보존한다.

**Q1. 라우트명: `/me` vs `/about` vs 기타**
추천: `/me`. 근거 — (1) "나를 소개하는 개인 허브"라는 맥락이 명확하다. (2) `/about`은 회사 소개 페이지 뉘앙스가 강해 개인 권위 허브와 어긋난다. (3) SNS bio 링크 목적지로 `gyeol.page/me`는 직관적이다. (4) `/card`(명함)와 역할이 구분된다. 반론이 있다면 `/shannon`도 가능하나, 도메인이 이미 Shannon의 것이므로 `/me`가 충분히 개인적이다.

**Q2. `ai.gyeol.page` 서브도메인을 허브(`/me`) vs `/ai` 중 어디에**
추천: `ai.gyeol.page` → `/ai` 유지. 근거 — `ai.gyeol.page`는 강의 페이지 직행 링크로 이미 설정 예정이고, 숨고·스레드에서 "AI 강의 문의"를 검색한 사람은 강의 랜딩에 직접 도달하는 것이 전환에 유리하다. 개인 허브(`/me`)는 `gyeol.page/me`로 충분히 도달 가능하다. SNS bio에는 `gyeol.page/me`를 사용한다. 단, 향후 `shannon.gyeol.page` 또는 `s.gyeol.page` 같은 개인 서브도메인을 `/me`로 연결하는 것은 검토 가능하다.

**Q3. 허브를 기존 `/card` 확장 vs 신규 페이지**
추천: 신규 페이지(`/me`). 근거 — `/card`는 오프라인 QR 스캔용 모바일 최우선 온라인 명함이고, 서사·권위·라우팅을 담은 허브와 목적이 다르다. 두 페이지는 교차 링크로 연결하되(허브에서 "명함 보기 →", 명함 뒷면에서 "더 보기 →") 분리를 유지한다. 코드 레벨에서는 `src/features/card/lib/profile.ts` 공유로 중복을 최소화한다.

**Q4. 실적/포트폴리오를 허브에 얼마나**
추천: 링크만. 근거 — 결 웹 제작 포트폴리오(`dewstone.kr` 등)는 `gyeol.page/#work` 또는 `/work`에 이미 있다. 허브에서 중복 노출하면 유지 관리 이중화 문제가 생긴다. S5에서 "포트폴리오 보기 →" 링크 하나로 연결하고, 강의 수강생 후기만 허브 전용 콘텐츠로 관리한다.
